# `salessystem` 接口接入分阶段方案

基于以下内容整理：

- 接口文档：[payment-system-前端对接接口文档-排除AI.md](C:\Users\朱伟杰\Desktop\多租户系统\payment-system-前端对接接口文档-排除AI.md)
- 当前前端项目：`salessystem`

## 目标

把当前以静态页面和本地 mock 为主的 `salessystem`，分阶段接入真实后端接口，尽量做到：

- 先打通公共底座，避免后面每个页面重复改
- 先接用户主流程，再接商户端，再接管理端
- 优先使用 `v1/app`、`v1/merchant`、`v1/admin` 三套新接口
- 尽量不碰旧版接口，除非新接口缺失或联调受阻

## 接入原则

1. 只对接文档中的 `v1` 新接口，旧接口暂不作为主方案。
2. 先做“能跑通主链路”，再做筛选、分页、边界优化。
3. 先统一请求层、鉴权、错误处理、数据类型，再逐页替换 mock。
4. 支付结果不能只靠前端跳转成功页，必须结合支付状态查询接口确认。
5. 商户端所有带 `tenantId` 的接口，必须先统一处理“当前商户上下文”。

## 已核对的后端事实

这部分基于 `payment-system` 后端代码核对，优先级高于接口文档措辞。

### 1. 接口基址不是根路径

- 后端 `application.yml` 中配置了：
  - `server.port: 8080`
  - `server.servlet.context-path: /api`
- 所以前端实际请求基址应为：
  - `http://<host>:8080/api`
- 也就是说文档里的 `/v1/app/...`，前端真正请求时应拼成：
  - `/api/v1/app/...`

### 2. Sa-Token 请求头名称已确认

- `application.yml` 中已明确：
  - `sa-token.token-name: Authorization`
- 因此前端默认把 token 放进请求头：
  - `Authorization: <token>`

### 3. 统一返回结构已确认

- 后端统一返回 `Result<T>`：
  - `code`
  - `message`
  - `data`
  - `timestamp`
- 成功码为 `200`
- 错误默认可能是 `500`，也可能是业务自定义 code

### 4. 登录返回体三端不完全一致

- 用户端登录：
  - `POST /v1/app/auth/login/password`
  - `POST /v1/app/auth/login/sms`
  - `POST /v1/app/auth/login/third-party`
  - 返回值：`Result<String>`，也就是纯 token

- 商户端登录：
  - `POST /v1/merchant/auth/login`
  - 返回值：`Result<V1MerchantSessionVO>`
  - 除 token 外，还会带：
    - `tenantId`
    - `tenantName`
    - `employeeRole`
    - `tenants`

- 管理端登录：
  - `POST /v1/admin/auth/login`
  - 返回值：`Result<String>`，也是纯 token
  - 管理员会话信息需要再调：
    - `GET /v1/admin/auth/session`

### 5. 用户端短信登录和第三方登录当前仍复用同一个 DTO

- 从 `V1AppAuthController` 看：
  - `/login/password`
  - `/login/sms`
  - `/login/third-party`
- 当前都复用了 `PlatformLoginDTO`
- 前端接入时先不要自行假设验证码字段结构，建议先按文档当前版本和后端联调确认

### 6. 商户端依赖平台登录态和 tenantId

- 商户控制器内部通过 `PlatformSessionHelper.getPlatformUserId()` 取当前平台用户
- 再通过 `tenantId` 做 `requireEmployee(tenantId, currentUserId)` 校验
- 这意味着：
  - 商户端不能只保存 token
  - 还必须在前端保存“当前选中的 tenantId”

### 7. 分页参数命名已确认

- 当前 v1 控制器分页参数统一使用：
  - `current`
  - `size`
- 不要在前端用成：
  - `page`
  - `pageNum`
  - `pageSize`

### 8. 支付状态同步是 POST

- 用户支付单状态同步接口是：
  - `POST /v1/app/payment-bills/{billNo}/sync`
- 前端轮询或手动刷新时要注意方法不是 `GET`

### 9. 商户规则与提现接口可直接按页面对接

- 商户规则：
  - `GET /v1/merchant/tenants/{tenantId}/points-rule`
  - `PUT /v1/merchant/tenants/{tenantId}/points-rule`
  - `GET /v1/merchant/tenants/{tenantId}/recharge-rules`
  - `PUT /v1/merchant/tenants/{tenantId}/recharge-rules`

- 商户提现：
  - `GET /v1/merchant/tenants/{tenantId}/withdrawals/balance`
  - `GET /v1/merchant/tenants/{tenantId}/withdrawals`
  - `POST /v1/merchant/tenants/{tenantId}/withdrawals`

### 10. 管理端权限控制是真实存在的

- 管理端不是“登录即可全通”
- 后端用了大量 `@SaCheckPermission(...)`
- 这意味着前端要提前考虑：
  - 权限不足时的页面提示
  - 按钮级隐藏或禁用
  - 403/无权限统一处理

## 建议拆分为 7 个部分

## 第一部分：公共底座

这一部分先不接业务页面，先把全局基础设施搭好。

### 要完成的内容

- 环境变量配置
  - `VITE_API_BASE_URL`
  - 如有需要再补 `VITE_UPLOAD_BASE_URL`
  - 本项目建议默认写成：
    - `VITE_API_BASE_URL=http://localhost:8080/api`

- 统一请求层
  - 建议新增：
    - `src/services/http.ts`
    - `src/services/request.ts`
    - `src/services/modules/`
  - 可以直接引入 `axios` 作为统一请求库
  - 建议在 `http.ts` 中统一完成：
    - `baseURL`
    - 超时时间
    - 请求拦截器
    - 响应拦截器
    - token 注入
    - 通用错误提示

- 统一 token 管理
  - 用户端 token
  - 商户端 token
  - 管理端 token
  - 是否共用一个 token 存储键，要结合后端返回和登录逻辑再定
  - 请求头统一使用：`Authorization`

- 统一响应处理
  - 适配文档中的返回结构：`code`、`message`、`data`、`timestamp`
  - 统一处理登录失效、无权限、服务异常

- 统一类型定义
  - 建议新增：
    - `src/types/api.ts`
    - `src/types/auth.ts`
    - `src/types/user.ts`
    - `src/types/order.ts`
    - `src/types/merchant.ts`
    - `src/types/admin.ts`

- 统一会话上下文
  - 当前登录角色
  - 当前用户信息
  - 当前商户 `tenantId`
  - 当前管理员会话
  - 当前商户可访问的 `tenants`

### 验收标准

- 能从环境变量读取后端地址
- 页面里不再直接写死 mock 数据请求逻辑
- 任意接口调用都能统一带 token、统一报错

## 推荐实际执行顺序

建议按下面顺序开始做，而不是多端同时推进：

1. 公共底座
2. 用户端基础链路
3. 用户端交易链路
4. 商户端业务链路
5. 商户端财务与运营
6. 管理端基础治理
7. 管理端交易结算与收尾联调

## 每一部分的交付物

每完成一个部分，建议至少交付这些内容：

- 页面真实接口替换完成
- 对应 service 模块完成
- 类型定义完成
- 错误态和空态补齐
- 本阶段联调记录
- 已知问题清单

## 不建议现在就做的事

- 不建议先接旧版 `/user`、`/order`、`/product` 等接口
- 不建议先接支付回调接口
- 不建议一开始就做全量筛选、导出、复杂统计图优化
- 不建议在底座没统一前逐页零散写请求
