# 第一部分：公共底座完成情况

本文档记录 `salessystem` 在“接口接入第一部分：公共底座”中已经完成的工作。

## 一、本次目标

本阶段目标不是直接把页面改成真实接口，而是先搭好一套可复用的前端接口基础设施，避免后续每个页面重复写请求逻辑。

目标包括：

- 引入统一请求库
- 统一后端地址配置
- 统一 token 注入方式
- 统一接口返回结构处理
- 统一错误处理
- 搭建首批 service 模块
- 搭建基础类型定义

## 三、后端关键事实已核对

为了避免对接错误，这一阶段还同步核对了 `payment-system` 后端代码，已确认：

- 后端基础路径是 `/api`
- Sa-Token 请求头名称是 `Authorization`
- 用户端登录返回的是纯 token
- 管理端登录返回的是纯 token
- 商户端登录返回的是完整 session 对象
- 商户端后续接口依赖 `tenantId`
- 分页参数统一使用 `current` 和 `size`
- 支付状态同步接口是 `POST`

这些结论已经同步写入：

- [接口接入分阶段方案.md](/C:/Users/朱伟杰/Desktop/多租户系统/salessystem/接口接入分阶段方案.md)
