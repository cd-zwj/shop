## 二、完成内容

### 1. Controller 下沉到 Service（#6）

将三个 Controller 中残留的 Mapper 直接调用全部迁移到 Service 层：

| Controller | 新增/扩展的 Service | 下沉的能力 |
|---|---|---|
| `V1AppCatalogController` | 新增 `AppCatalogService` + `AppCatalogServiceImpl` | 商户列表、商户详情、商品列表、ES 搜索代理、商品详情 + VIEW 行为埋点 |
| `V1MerchantProductController` | 新增 `V1MerchantProductService` + `V1MerchantProductServiceImpl` | 商户商品分页/详情/CRUD、库存初始化、ES 索引消息发布、`requireEmployee` 权限校验前置 |
| `V1AppNotificationController` | 扩展 `UserNotificationService` 接口 | 新增 `countUnread`、`markAllRead`，`markAllRead` 写入 `readTime` 并返回受影响条数 |

调整后三个 Controller 退化为「路由 + VO 转换」，无任何 Mapper 注入。`V1MerchantProductServiceImpl` 写路径全部加 `@Transactional(rollbackFor = Exception.class)`，保证「写商品 → 写库存 → 发 MQ 索引消息」处于同一事务。

### 3. Elasticsearch 启动策略（#8）

采用「搜索默认关、按需开」方案，避免 `docker compose up` 因连不上 ES 持续刷错。

**代码与配置变更：**

- `payment-system/src/main/java/com/payment/config/ElasticsearchConfig.java`：`@ConditionalOnProperty(... matchIfMissing = false)`，默认不装配 ES Bean，附加启用步骤 Javadoc。
- `payment-system/src/main/resources/application.yml`：
  - `spring.elasticsearch.*` 块加注释说明
  - 新增 `app.search.enabled: ${APP_SEARCH_ENABLED:false}` 显式开关
- `payment-system/src/main/java/com/payment/service/impl/ProductSearchServiceImpl.java`：`searchProducts` / `searchByCategory` 在 `elasticsearchOperations == null` 时直接走 `queryProducts` DB fallback（DEBUG 日志），不再以「先抛 `IllegalStateException` 再 catch」实现降级，启动日志不再含搜索 ERROR。
- `docker-compose.yml`：
  - `backend.environment` 显式注入 `APP_SEARCH_ENABLED=false` 与 `ES_URIS=http://elasticsearch:9200`
  - 附 `elasticsearch` 可选 service 注释块（含 `es-data` 卷与启用步骤）

**测试：**

`payment-system/src/test/java/com/payment/service/impl/ProductSearchServiceImplTest.java` 新增 3 条 ES 禁用回归：
- `searchProductsShouldFallbackToDatabaseWhenElasticsearchDisabled`
- `searchByCategoryShouldFallbackToDatabaseWhenElasticsearchDisabled`
- `syncProductShouldSkipWhenRepositoryDisabled`

原 ES 命中与 ES 抛异常 fallback 两条单测保留。

## 四、对运行环境的影响

- 生产 `docker compose up` 后，backend 启动日志不再出现 ES 连接 ERROR；商品搜索默认走 MySQL 模糊匹配。
- 需要启用 ES 时，按 `docker-compose.yml` 注释步骤：取消 `elasticsearch` service 注释 + `APP_SEARCH_ENABLED=true` + `depends_on` 增加 `elasticsearch` 即可。
- `application-dev.yml` 未引入新配置项，本地开发若需 ES 搜索直接 `APP_SEARCH_ENABLED=true` 环境变量启动。
- Flyway `V*.sql` 与裸 `sql/*.sql` 不再产生编号歧义，新增迁移可直接从 `32_*.sql` 开始。
