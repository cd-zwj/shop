## 逐项详情

### ✅ #5 健康检查端点

`pom.xml` 已添加 `spring-boot-starter-actuator`，`application.yml` 已配置。暴露了 `/actuator/health`、`/actuator/info`、`/actuator/prometheus`。策略合理（`when-authorized` 控制 details 级别）。

### ✅ #6 监控指标

`pom.xml` 已添加 `micrometer-registry-prometheus`，与 #5 共用 `/actuator/prometheus` 端点。

### ✅ #7 Logback 配置

`logback-spring.xml` 双 profile 配置：dev 用 Console appender + com.payment DEBUG；prod 用滚动文件 30 天保留 / 2GB 上限 + JSON 格式 + ERROR 独立文件分离。满足审计要求。

### ⚠️ #8 安全响应头 — 部分修复

`WebConfig.java` 通过 `OncePerRequestFilter` 添加了 5 个响应头：
- ✅ X-Content-Type-Options: nosniff
- ✅ X-Frame-Options: DENY
- ✅ X-XSS-Protection: 1; mode=block
- ✅ Referrer-Policy: strict-origin-when-cross-origin
- ✅ Cache-Control: no-store（额外添加）

**缺失 2 项：Strict-Transport-Security (HSTS) 和 Content-Security-Policy (CSP)。** HSTS 是生产环境关键头；CSP 建议以 `default-src 'self'` 作为基线。

### ✅ #9.a CouponServiceImpl N+1

`batchLoadScopes()` 方法（line 962-974）批量 IN 查询 CouponScope，在 `listAvailableTemplates`（line 227-231）调用，将循环内单条 scope 查询替换为一次批量 IN。

注意：`isCouponTemplateVisibleToTenant`（line 851）和 `isTemplateVisibleForTenantAndUser`（line 856）仍调用单条 `listScopes`，但仅在低流量的 `getUserCouponTemplates` 路径使用，可接受。

### ❌ #9.b PromotionServiceImpl N+1 — 未修复

`matchActivity`（line 263）在 `matchPromotions`（line 177-178）的 `stream().map()` 中逐活动调用，每次执行一条 `activityRuleMapper.selectList`。N+1 模式完全未动。

**修复方向**：先收集所有 activity ID → 一次 IN 查询所有 ActivityRule → 按 activityId 分组。

**缺失 1 条：`member_points_log` 覆盖索引。** `import_all.sql` 已正确引用 30 号迁移。
