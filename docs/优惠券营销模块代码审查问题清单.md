## 一、定价引擎缺陷

### 1.1 折扣券封顶金额未生效 — HIGH ✅ 已修复

**涉及文件**

| 文件 | 行号 |
|------|------|
| `sql/15_coupon_marketing.sql` | 18 |
| `entity/CouponTemplate.java` | maxDiscountAmount 字段 |
| `dto/pricing/CouponDiscountCandidateDTO.java` | 全文 |
| `service/impl/CouponServiceImpl.java` | 349–358 |
| `service/impl/OrderPricingServiceImpl.java` | 110–116 |

**现状**

SQL 表 `coupon_template` 定义了 `max_discount_amount`，`CouponTemplate` 实体也映射了该字段。但 `resolveCouponCandidate()` 构建 `CouponDiscountCandidateDTO` 时未传递该字段，`CouponDiscountCandidateDTO` 类本身也没有 `maxDiscountAmount` 属性。

定价引擎 `calculateCouponDiscount()` 对 `DISCOUNT_RATE` 类型的计算为：

```java
return eligibleAmount.multiply(BigDecimal.ONE.subtract(rate));
```

没有 `min(maxDiscountAmount)` 兜底。

**后果**

配置"85 折、封顶 20 元"的折扣券，用户下 1000 元订单实际减免 150 元，远超商户预期。封顶约束形同虚设。

**修复**

1. `resolveCouponCandidate` 传递 `maxDiscountAmount` 和 `stackStrategy` 到 `CouponDiscountCandidateDTO`
2. `OrderPricingServiceImpl.calculateCouponDiscount` 对 `DISCOUNT_RATE` 计算结果加 `.min(maxDiscountAmount)` 封顶

---

### 1.2 叠加策略未执行 — HIGH ✅ 已修复

**涉及文件**

| 文件 | 行号 |
|------|------|
| `sql/15_coupon_marketing.sql` | 30 |
| `entity/CouponTemplate.java` | stackStrategy 字段 |
| `service/impl/OrderPricingServiceImpl.java` | 34–41 |

**现状**

`coupon_template.stack_strategy` 持久化了 `EXCLUSIVE`（不可叠加）和 `STACKABLE`（可叠加）两种策略。但 `OrderPricingServiceImpl.calculate()` 的逻辑始终是：

```java
BigDecimal activityDiscount = applyActivities(...);
BigDecimal couponDiscount = applyCoupon(..., totalAmount.subtract(activityDiscount), ...);
```

无论 `stack_strategy` 是什么值，活动折扣和优惠券折扣都会同时叠加应用。`stackStrategy` 字段从未被读取或判断。

**后果**

商户配置"不可叠加"券，用户仍然可以同时享受活动满减 + 优惠券抵扣，违背业务规则。

**修复**

`applyCoupon` 增加 `activityDiscount` 参数，若 `EXCLUSIVE` 且活动折扣 > 0，返回 0（券折扣不生效）。

## 二、并发安全缺陷

### 2.1 领券非原子，库存可超卖 — HIGH ✅ 已修复

**涉及文件**

| 文件 | 修复方式 |
|------|----------|
| `mapper/UserCouponMapper.java` | `claimCouponSlot` 原子 SQL |
| `service/impl/CouponServiceImpl.java` | 先 claim 后 insert |

**修复**

用 `UserCouponMapper.claimCouponSlot` 替代原有的 `ensureStock` + `ensurePerUserLimit` + `atomicDecrementStock`，一条 SQL 原子约束库存和限领：

```sql
UPDATE coupon_template SET received_count = received_count + 1, update_time = NOW()
WHERE id = #{templateId} AND deleted = 0
AND (total_stock <= 0 OR received_count < total_stock)
AND (per_user_limit <= 0 OR (
    SELECT COUNT(*) FROM user_coupon
    WHERE coupon_template_id = #{templateId}
    AND platform_user_id = #{platformUserId} AND deleted = 0
) < per_user_limit)
```

顺序：先 `claimCouponSlot` 抢占 → 成功后再 `INSERT user_coupon` → 再 `INSERT receive_record`。

---

### 2.2 券锁定/释放/核销不校验归属订单 — HIGH ✅ 已修复

**修复**

- `lockCoupon`：幂等判断（同一 orderId 已锁则直接返回）+ `updateById` affected rows 检查
- `releaseCoupon`：校验 `lockOrderId` 匹配 + `ensureUser` + 清空 lock 字段 + affected rows 检查
- `writeOffCoupon`：校验 `lockOrderId` 匹配 + affected rows 检查
- `expireCoupons`：清空 lock 字段 + affected rows 检查 + `continue` 跳过并发冲突

## 三、状态机缺陷

### 3.1 过期扫描会强行过期已锁定的券 — HIGH ✅ 已修复

**修复**

`expireCoupons()` 查询条件从 `status IN ('RECEIVED', 'LOCKED')` 改为 `status = 'RECEIVED'`。LOCKED 券的过期交给订单超时关闭流程处理（先释放再判过期）。

---

## 四、平台券语义混乱

### 4.1 领取时 tenantId 硬写，平台券跨商户失效 — HIGH ✅ 已修复

**修复**

1. `resolveCouponTenantId`：平台券返回 `null`
2. `listUserCoupons`：`tenantId = 当前商户 OR tenantId IS NULL` + 按模板 scope 过滤可见性
3. `ensureTenant`：`tenantId == null` 直接 return（平台券不限定商户）

---

### 4.2 PRODUCT/CATEGORY 范围的 tenantId 未校验 — HIGH ✅ 已修复

**修复**

1. `calculateEligibleAmount`：收集 PRODUCT/CATEGORY scope 时同时收集 `scope.tenantId`，若 `scopedTenantIds` 非空且当前 tenant 不在其中，返回 `BigDecimal.ZERO`
2. `isTemplateVisibleForTenantAndUser`：同样逻辑，当前 tenant 不在 scope tenantId 集合中时返回 `false`

## 六、审查追加问题详解

### R-1 releaseCoupon 缺用户归属校验 — CRITICAL ✅ 已修复

`releaseCoupon` 只校验 `tenantId`，不校验 `platformUserId`。同租户用户 A 可释放用户 B 的锁定券。

**修复**：`releaseCoupon` 签名增加 `platformUserId` 参数，方法体加 `ensureUser(coupon, platformUserId)`。

---

### R-2 积分算术溢出 — CRITICAL ✅ 已修复

`holdPoints` / `grantPoints` / `releasePointsHold` 使用 `Integer` 加减，极端情况可溢出。

**修复**：改用 `Math.addExact` / `Math.subtractExact`，溢出时抛 `ArithmeticException`。

---

### R-3 释放/过期未清 lock 字段 — HIGH ✅ 已修复

`releaseCoupon` 和 `expireCoupons` 状态变更后未清空 `lockOrderId` / `lockOrderNo` / `lockTime`，导致脏数据残留。

**修复**：状态变更时显式设置三个字段为 `null`。

---

### R-4 expireCoupons 无租户边界 — HIGH ✅ 已修复

过期扫描查询未过滤 `tenantId`，误传未来时间可过期全量券。

**修复**：`expireCoupons` 增加可选 `Long tenantId` 参数，非空时加 `.eq(UserCoupon::getTenantId, tenantId)` 条件。

---

### R-5 CouponTemplate.version 缺 @Version — HIGH ✅ 已修复

`CouponTemplate.version` 字段未加 `@Version` 注解，`activateTemplate` / `disableTemplate` 等 `updateById` 调用无乐观锁保护。

**修复**：`CouponTemplate.version` 加 `@Version` 注解。

---

### R-6 重复查询 scope — MEDIUM ✅ 已修复

`isCouponTemplateVisibleToTenant` 和 `isTemplateVisibleForTenantAndUser` 各自独立查询 scope，同一模板两次 DB 查询。

**修复**：提取 `isVisibleWithScopes(template, tenantId, platformUserId, scopes)` 共享方法。
