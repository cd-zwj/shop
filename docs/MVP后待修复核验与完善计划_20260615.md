## 二、完善计划

### 第一批: 稳定性与权限实时性

1. 关闭 #1，补一条回归检查即可
   - 不改退款代码，先把清单状态更新为“未复现/已修”。
   - 增加一次全仓静态检查或单测约束：禁止新增 `tryLock(waitTime, unit)` 两参调用。

2. 完善权限缓存失效
   - 新增 `PermissionCacheInvalidationService` 或类似小服务，统一封装 Sa-Token Session key 清理。
   - 清理 key 覆盖 `permissions`、`roles`，并预留按用户、按角色批量失效方法。
   - `UserPermissionServiceImpl` 改为调用该服务，避免 catch 后静默吞掉失败；至少记录 warn 日志。
   - 如果后续开放用户角色分配、角色权限维护，必须在对应写操作后调用失效服务。
   - 增加单测覆盖授权、撤权、全量设置权限后 session key 被删除。

### 第二批: 核心功能补齐

3. 接通 App 密码重置
   - 后端复用 `PlatformEmailAccountService`，在 `V1AppAuthController` 增加:
     - `POST /v1/app/auth/password/reset/send-code`
     - `POST /v1/app/auth/password/reset/verify`
   - DTO 使用 `@Email`、`@NotBlank`、密码强度校验；接口加 `@RateLimit`。
   - 前端新增 `ResetPassword.tsx`，流程为邮箱/账号输入、发送验证码、设置新密码。
   - `Login.tsx` 的“忘记密码”改为跳转页面，不再 toast 占位。
   - 补后端 Controller/Service 测试和前端 service/page 测试。

4. 建立会员降级策略
   - 数据库和实体新增 `downgrade_growth`、`level_validity_days`，必要时为会员关系表增加 `level_expire_time`。
   - `MemberGrowthService` 拆出“计算目标等级”方法，同时支持升级与降级。
   - 新增 `MemberLevelScheduler`，按月或季度扫描租户会员，低于阈值或等级过期时降级。
   - 先不做成长值衰减，除非产品明确需要；衰减会影响历史权益口径。
   - 补 `MemberGrowthServiceImplTest` 和 Scheduler 测试。

5. 建立积分过期
   - `member_points_log` 增加 `expire_time`、`expired_points` 或独立积分批次表；建议用批次表，避免只靠汇总日志难以按先进先出过期。
   - 新增 `PointsExpireScheduler`，每日扫描到期未消耗批次，写入 `EXPIRE` 日志并扣减账户余额。
   - 前端 `Points.tsx` 展示即将过期积分，接口返回 30 天内到期汇总。
   - 补并发扣减、重复执行幂等、余额不足保护测试。

### 第三批: 结构与运行环境治理

6. Controller 下沉到 Service
   - `V1AppCatalogController` 改为调用 `AppCatalogService`，保留行为日志调用或下沉到 service。
   - `V1AppNotificationController` 将未读数、全部已读移动到 `UserNotificationService`。
   - `V1MerchantProductController` 新增 `V1MerchantProductService`，承接列表、新增、修改、删除、库存初始化、ES 索引发布。
   - 重构时先写 Controller contract 测试锁定 API 响应，再迁移逻辑。

7. 整理 SQL 迁移编号
   - 短期重命名:
     - `19_message_retry.sql` -> `20_message_retry.sql`
     - `20_platform_auth_provider.sql` -> `21_platform_auth_provider.sql`
     - 后续文件顺延或补 `25_xxx.sql`
   - 同步更新 `import_all.sql` 和 `sql/README.md`。
   - 中期迁移到 Flyway，使用 `src/main/resources/db/migration/V*.sql` 作为唯一执行入口。

8. 修正 Elasticsearch 启动策略
   - 如果 MVP 必须有搜索能力，在 `docker-compose.yml` 增加 Elasticsearch 服务，并设置 `ES_URIS=http://elasticsearch:9200`。
   - 如果搜索是可选能力，将 `app.search.enabled` 默认改为 `false`，compose 环境显式关闭；需要 ES 的环境再打开。
   - `ProductSearchServiceImpl` 保持降级查询，但启动阶段不应持续输出连接错误。

### 第四批: 体验一致性与测试补齐

9. 统一前端错误处理
   - 制定页面规则: 阻断型加载失败用页面 `error + retry`，非阻断型操作失败用 toast，后台增强数据失败可降级但需 debug 日志。
   - 增加全局 `unhandledrejection` 和 `error` 监听，在 `main.tsx` 或独立 `errorEvents.ts` 注册。
   - 增加网络状态 hook，离线时禁用支付/下单等关键按钮并展示 toast。
   - 清理 `Home`、`Discovery`、`Points` 的静默 catch。

10. 补前端关键测试
   - 优先级: `orderCheckout.ts`、`AuthContext.tsx`、`ErrorBoundary.tsx`、`Cart.tsx`、`ProductDetails.tsx`。
   - 对页面测试使用 React Testing Library，mock service 层，不连真实后端。
   - 覆盖支付方式选择、下单 payload、登录态恢复、错误边界兜底、购买入口跳转。

11. 补后端关键集成测试
   - 新增支付完整链路集成测试: 下单、创建支付单、回调验签通过、账单和业务订单状态更新。
   - 新增退款完整链路集成测试: 申请、审核、提交退款、回调/对账确认。
   - 新增 `DeadLetterRecoveryScheduler` 集成测试，验证重投成功、失败重试、幂等状态。
   - 新增多租户隔离测试，覆盖查询、写入、越权访问拒绝。
