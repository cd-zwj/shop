## 三、架构设计决策

| 决策点 | 选择 | 理由 |
|--------|------|------|
| 短信供应商 | 策略模式 SmsSender 接口 | 与 PaymentProvider 一致，mock/aliyun/tencent 可配置切换 |
| DTO 设计 | 新增独立 SmsLoginDTO | PlatformLoginDTO.password 校验注解语义不对，独立 DTO 更清晰 |
| 前端状态 | 新增独立 phone + smsCode | 避免 password 和验证码混用，UI 语义明确 |
| 阿里云 SDK | 暂不引入 | 先用 MockSmsSender，生产部署时再接入真实供应商 |
| phone 索引 | 已有 `UNIQUE KEY uk_phone` | 无需新增迁移脚本 |

## 四、API 变更

### 新增接口

```
POST /api/v1/app/auth/sms/send-code
Body: { phone, captchaKey, captchaCode }
Response: Result<Void>
限流: @RateLimit(60s/1次/手机号+IP)
```

### 变更接口

```
POST /api/v1/app/auth/login/sms
Before: Body: { username, password, captchaKey, captchaCode }
After:  Body: { phone, smsCode, captchaKey, captchaCode }
Response: Result<String> (token)
```

> ⚠️ Breaking Change：前后端已同步修改，无兼容性问题。

## 六、SMS 配置说明

`application.yml` 新增配置段：

```yaml
app:
  auth:
    sms:
      enabled: ${SMS_ENABLED:true}
      provider: ${SMS_PROVIDER:mock}        # mock | aliyun | tencent
      sign-name: ${SMS_SIGN_NAME:}
      template-code: ${SMS_TEMPLATE_CODE:}
```

开发环境默认 `provider=mock`，验证码通过日志输出（`log.info`）。切换到真实供应商时：
1. 实现 `SmsSender` 接口（如 `AliyunSmsSender`）
2. 设置 `SMS_PROVIDER=aliyun`
3. 配置签名和模板
