### 1B 提现资金安全修复

**目标**：杜绝“拒绝提现但余额冻结不归还”和“审批并发重复放款”。

#### 问题 1：拒绝提现余额冻结

- `WithdrawalServiceImpl` 在解冻失败后仍继续标记提现失败状态
- 属于 P0 资金安全问题

#### 任务 A

1. 修改拒绝提现逻辑：
   - 冻结余额不足时直接抛出 `BusinessException`（`requireFrozenBalance` 校验）
   - 解冻失败不继续更新提现状态为拒绝
   - 事务回滚
2. 增加明确业务异常：
   - `throw new BusinessException(...)`
3. 保留重试，但最终失败必须终止拒绝流程
4. 明确日志告警与人工介入入口

#### 问题 2：提现审批并发风险

- `approveWithdrawal(Long)` 检查状态与更新状态不是原子操作
- `Withdrawal` 实体没有 `@Version`

#### 任务 B

1. 推荐使用数据库条件更新：
   ```sql
   UPDATE withdrawal
   SET status = 1, audit_time = now, audit_user_id = :auditUserId
   WHERE id = :id AND status = 0
   ```
2. 若更新行数为 0：
   - 抛业务异常“已处理，请勿重复审批”
3. 冻结余额扣减与状态更新保持同一事务
4. 管理端审批/拒绝接口统一传递真实 `approverId`（来源 `PlatformSessionHelper.getPlatformUserId()`）

#### 预期改动文件

| 文件 | 操作 |
|---|---|
| `WithdrawalServiceImpl.java` | 修改 |
| `WithdrawalMapper.java` | 视条件更新实现情况决定 |
| 单测文件 | 新增/修改 |

#### 测试用例

- 拒绝提现时余额解冻成功
- 解冻失败时拒绝流程回滚
- 审批单重复提交，第二次失败
- 并发审批模拟不会重复扣减


### 1C MQ 消费幂等修复

**目标**：防止 RabbitMQ 重发导致重复充值。

#### 涉及问题

- `PaymentV1Consumer` 未调用 `MessageIdempotentService`
- 虽有业务状态守卫，但仍存在并发重复风险

#### 任务

1. `PaymentV1Consumer` 注入 `MessageIdempotentService`
2. 消费前调用：
   - `messageIdempotentService.isProcessed(messageId, queueName)`
3. 若已处理，跳过本次消息
4. 成功后调用：
   - `recordSuccess(...)`
5. 失败时保留原有 MQ 重试/死信语义
6. 幂等键建议：
   - 消息自带头 `messageId`
   - 无天然 ID 时，使用 `业务单号 + queueName`

#### 预期改动文件

| 文件 | 操作 |
|---|---|
| `PaymentV1Consumer.java` | 修改 |
| `MessageIdempotentService.java` | 可选扩展 |
| `MessageIdempotentServiceImpl.java` | 可选扩展 |
| 测试文件 | 新增 |

#### 测试用例

- 重复消息只处理一次
- 第一条消息成功处理后写幂等记录
- 处理失败不写成功记录
- 并发重复消息不重复扣减充值

#### 验证

```bash
cd payment-system
mvn test -Dtest=PaymentV1ConsumerTest
```

#### 验收

- [x] MQ 消费具备幂等能力
- [ ] 重复消费不再导致重复充值

## 风险与缓解

| 风险 | 等级 | 缓解措施 |
|---|---:|---|
| 提现资金修复影响真实资金流 | 高 | 先补充单测，事务回滚，条件更新防并发 |
| MQ 幂等键设计不当误跳消息 | 高 | 使用业务单号+队列名，覆盖成功/失败/并发测试 |
| 权限码新增后商户员工权限不足 | 中高 | 同步补权限初始化脚本并验证角色绑定 |
| Sa-Token 单会话影响多端体验 | 中 | 按环境区分策略，生产需人工确认 |
| 一次开启 TypeScript strict 报错过多 | 中 | 渐进开启，不一次性启用全部严格规则 |
| 删除废弃代码误删仍在用功能 | 中 | 全局搜索调用关系确认后再删除 |
