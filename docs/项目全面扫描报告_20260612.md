### 2. 提现拒绝后余额永久冻结 — 资金丢失

**模块**：后端 / 资金安全
**文件**：`WithdrawalServiceImpl.java:152-160`

**描述**：当商户拒绝提现申请时，解冻操作会重试 2 次。如果 2 次均失败，代码仅打印 `log.warn` 后继续将提现状态标记为"已拒绝"，**但冻结的余额不会归还到可用余额**。

```java
// 当前代码（第 152-160 行）
if (attempt == 2) {
    log.warn("拒绝提现解冻余额失败，请手动处理 withdrawalId={}", dto.getWithdrawalId());
}
// 即使解冻失败，仍继续执行 withdrawal.setStatus(2) 和 updateById
```

**影响**：资金永久冻结，商户无法使用该笔金额。
**同类问题**：`rejectWithdrawal(Long, String)` 方法（第 394 行）存在同样缺陷。

**修复方案**：解冻失败时应抛出异常或进入人工处理队列，禁止跳过解冻直接标记状态。

### 3. 提现审批无幂等保障 — 并发放款风险

**模块**：后端 / 资金安全
**文件**：`WithdrawalServiceImpl.java:328-365`

**描述**：`approveWithdrawal(Long withdrawalId)` 方法先检查 `withdrawal.getStatus() != 0` 再执行更新，但检查与更新不是原子操作。两个并发审批请求均可通过状态检查，导致重复放款。

**修复方案**：
- 方案 A：使用 `@Version` 乐观锁
- 方案 B：使用 `UPDATE ... WHERE status = 0` 数据库级原子操作

---

### 4. 消息幂等服务未接入 Consumer — MQ 重发导致重复充值

**模块**：后端 / MQ 可靠性
**文件**：`MessageIdempotentServiceImpl.java` / `PaymentV1Consumer.java`

**描述**：`MessageIdempotentServiceImpl.recordSuccess()` 可以记录已处理的消息，但 `PaymentV1Consumer.handleRechargeSuccess()` **不调用** `messageIdempotentService.isProcessed()` 进行去重校验。RabbitMQ 消息重发时会导致用户钱包重复充值。

**修复方案**：在 Consumer 处理逻辑开头添加幂等检查：
```java
if (messageIdempotentService.isProcessed(messageId)) {
    log.info("消息已处理，跳过: {}", messageId);
    return;
}
```

### 5. 微信登录认证绕过 — 无服务端验证

**模块**：后端 / 认证安全
**文件**：`UserServiceImpl.java:128`

**描述**：微信小程序登录接口直接将客户端传入的 `code` 拼接为 openid：

```java
// TODO: 实际项目中需要调用微信API验证code并获取openid
String openid = "wx_" + dto.getCode();
```

**影响**：任意字符串均可作为用户身份登录，无需微信授权。这是一个**完全开放的认证绕过漏洞**。

**修复方案**：调用微信 `code2Session` 接口验证 code 并获取真实 openid。

### 6. 前端 ErrorBoundary 无法捕获渲染错误

**模块**：前端
**文件**：`salessystem/src/components/ErrorBoundary.tsx`

**描述**：ErrorBoundary 使用函数组件 + `try/catch` 实现，但 React 错误边界**必须**使用 Class 组件 + `componentDidCatch` + `getDerivedStateFromError`。函数组件的 try/catch 仅能捕获初始渲染阶段的同步错误，无法捕获子组件 re-render 或异步错误。

**影响**：子组件渲染异常时显示 React 白屏（White Screen of Death），而非自定义降级 UI。

**修复方案**：改为 Class 组件实现：
```tsx
class ErrorBoundary extends React.Component<Props, State> {
  static getDerivedStateFromError(error: Error) {
    return { hasError: true, error };
  }
  componentDidCatch(error: Error, errorInfo: ErrorInfo) {
    console.error('ErrorBoundary caught:', error, errorInfo);
  }
  render() { /* ... */ }
}
```

### 8. SQL 拼接注入风险

**模块**：后端 / 安全
**文件**：`V1MerchantFinanceController.java:183-184`

```java
.inSql(UnifiedWalletLog::getBizNo,
    "SELECT order_no FROM sales_order WHERE tenant_id = " + tenantId + " AND deleted = 0");
```

**当前风险等级**：低（`tenantId` 为 `Long` 类型，Spring 自动进行类型转换）

### 11. 文件上传未验证 tenantId 归属

### 12. Sa-Token 多端并发登录 + 无 Token 黑名单

**模块**：后端 / 安全
**文件**：`application.yml:157-160`

```yaml
sa-token:
  is-concurrent: true    # 允许多端同时登录
  is-share: true          # 同一 Token 可跨标签页共享
  timeout: 86400           # Token 有效期 24 小时
  active-timeout: -1       # 无活跃超时（永不过期）
```

**影响**：
- 用户可拥有无限活跃会话
- 被盗 Token 在 24 小时内无法被服务端主动撤销
- 密码修改/封禁后旧 Token 仍然有效

**修复方案**：
- 生产环境设置 `is-concurrent: false`（强制单会话）
- 实现 Token 黑名单机制（密码修改/封禁时加入黑名单）
- 设置合理的 `active-timeout`
